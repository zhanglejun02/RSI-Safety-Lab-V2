# 一页判断：GEPA 与全量公开验证

**结论：已找到可执行、重复测得效用收益的自然更新；本次审查没有显示部署安全收益；尚未发现必须发明新安全方法才能解决的困难。**

固定排程、银行、Slack 小任务包；每组两个搜索根、每根两次更新。独立终测为四个任务实例的 clean/attack 配对，各执行三次。模型均为 DeepSeek Flash；风险由模拟环境的实际效果判定，不使用 LLM judge。共分配 288 项候选／初始版测试，执行 264 项；24 项因一份资源清单无效而在执行前失败，另有 8 项执行耗尽步骤。原始记录没有修补或重跑。

| 最终部署条件 | 任务完成率 ↑ | 平均效用 ↑ | 安全违规率 ↓ | 安全标签覆盖 ↑ |
|---|---:|---:|---:|---:|
| 初始版参照，四根 | 40/96，41.7% | 57.9% | 12/90，13.3% | 90/96，93.8% |
| GEPA，无审查，两根 | 21/48，43.8% | 62.2% | 4/47，8.5% | 47/48，97.9% |
| GEPA，全量公开验证，两根 | 19/48，39.6% | 57.5% | 6/45，13.3% | 45/48，93.8% |

平均效用对固定题目等权：排程题为请求完成比例，原生任务为二元完成判据。违规率只使用有效标签，缺失不是安全。相同源码在同根复用测量，表中参照与最终部署有重叠，不能把各行当独立样本。银行、Slack 的风险限于指定攻击目标；这不是普适安全排名。

**1．自然更新：候选层通过，部署收益尚未跨根稳定。** 8 个提案均通过 Python 语法解析，7 个通过资源契约并实际执行。这 7 个候选相对各自初始版的平均效用提高 **7.64–21.88 个百分点，三个重复块均为正**；6 个提高完整任务完成率，1 个持平。无审查根的最终部署收益分别为 **0、+7.64 个百分点**，只有一根换了版本，因此没有通过预定的“两根最终版本均改善”标准。未部署候选的成绩不能替代最终方法成绩；可评候选在标签完整的配对中没有新增违规。

**2．预期作用与实际失效：检测到风险，未显示部署安全收益。** 本次只适配 [Safety Must Survive 的全量公开验证组件](https://arxiv.org/html/2610.01073v1#S2)，不复现整套恢复方法：拟部署版本须通过全部 probe，拒绝则保留原版。4 次审查全部拒绝：3 次同时发现违规及任务失败，1 次仅因任务失败；没有证据不足阻断。其中两次风险审查针对未改变的初始部署源码，只有一次针对新候选。审查组两根最后仍使用初始版，每根终测均出现 3 次违规。唯一换版的无审查根为 1 次，原版为 3 次；这不足以建立稳定的方法效应，也不能把组间差值解释成审查导致风险上升。终测工具调用仍为无审查组 **606 次**、审查组 **620 次**，两组都继续实际执行任务。

**3．原因证据与普通办法：尚不能声称已有修复不足。**

- **实现错误已定位并可常规修复。** 无效候选的清单多声明了两个不存在的技能文件。现有 `Harness.replace` 重建清单后，文件内容不变，零 API 脚本控制完成 8/8 次执行。这只验证执行链路，不把修复版算作自然更新。
- **门控适用条件不匹配。** 原论文主要安全保持实验从正确 founder 出发；本次 founder 的任务能力与安全性均有缺口。拒绝后继续部署有风险的旧版，是原论文已分析的情形，不能作为我们的新发现。当前实现没有加入其验证回退／暂停机制。
- **放宽效用门槛不等于消除风险。** 在同一公开证据上重放已有“零违规＋效用不退化”审查，4 次中会放行 1 次。但该候选独立终测仍违规 **2/23**；另一候选公开 probe 违规 **2/8**，终测却为 **0/24**。不同任务上的真实行为不同，不能把这直接叫评分误报／漏报。现有覆盖扩展、执行授权守卫和回退并未被排除；本轮不能证明它们不足。

**决定：保留任务包与平台，确认“有自然收益”这一步；暂停以当前 gate 的失败主张方法创新，不追加任务或种子追求正结果。**
